PostgreSQL Lab Portfolio
Комплекс лабораторных работ по проектированию, разработке и программированию баз данных в PostgreSQL. Проект демонстрирует полный цикл работы с БД: от создания схем до серверного программирования с триггерами и аудитом.
О проекте

Учебный проект, демонстрирующий профессиональную работу с PostgreSQL. Разработана полноценная база данных для управления персоналом предприятия, включающая:
- Нормализованную структуру с 6 взаимосвязанными таблицами
- Сложные ограничения целостности и валидацию данных
- Работу с массивами и транзакциями
- Наследование таблиц и секционирование
- Представления для упрощения доступа к данным
- Систему аудита всех изменений через триггеры
- Бизнес-логику на стороне БД (функции, процедуры, триггеры)

Стек технологий

- **PostgreSQL 15+**
- PL/pgSQL
- Business Studio (моделирование)
- DDL / DML / DCL
- Транзакции (REPEATABLE READ)
- Массивы
- Наследование таблиц
- Секционирование (PARTITION BY RANGE)
- Представления (VIEW)
- Триггеры
- Функции и процедуры

Структура базы данных

```
Schemas/
├── Persons/
│   ├── EMPLOYEE          # Сотрудники (центральная таблица)
│   ├── JOB                # Должности
│   └── job_history        # История изменений (аудит)
├── Organization/
│   ├── COMPANY            # Компании
│   └── DEPARTMENT         # Отделы
├── Location/
│   ├── COUNTRY            # Страны
│   └── CITY               # Города
└── equipment/             # Наследование (Lab 3)
    ├── devices            # Родительская: устройства
    ├── computers          # Дочерняя: компьютеры
    └── printers           # Дочерняя: принтеры
```

Лабораторные работы

Lab 1: Проектирование структуры БД

Создание логической модели данных с нуля.
Ключевые возможности:
- Создание схем (`Persons`, `Organization`, `Location`)
- Проектирование 6 взаимосвязанных таблиц
- Ограничения целостности:
  - `CHECK` (возраст ≥20 лет, зарплата 20000-100000)
  - `UNIQUE` (email, названия)
  - `FOREIGN KEY` с каскадными операциями
- Валидация email через регулярные выражения
- Вычисляемые столбцы (`Short_DEPT`)

**Файл:** `Лабораторная_работа_1_Федоренко.sql`

### Lab 2: Манипуляция данными и транзакции

Работа с данными и конкурентный доступ.

**Ключевые возможности:**
- Вставка данных с подзапросами
- **Массивы:** хранение нескольких телефонов сотрудника
- Операции с массивами:
  - `array_append` — добавление
  - Обращение по индексу — изменение
  - `array_remove` — удаление
- **Транзакции:** уровень изоляции `REPEATABLE READ`
- Демонстрация блокировок при параллельном доступе
- Каскадные операции (`ON UPDATE CASCADE`, `ON DELETE SET NULL`)

**Файл:** `Лабораторная_работа_2_Федоренко.sql`

### Lab 3: Наследование, секционирование, представления

Продвинутые возможности PostgreSQL.

**Наследование таблиц:**
```sql
-- Родительская таблица устройств
CREATE TABLE equipment.devices (id, inventory_number, device_name, ...);

-- Дочерние с дополнительными полями
CREATE TABLE equipment.computers (cpu_type, ram, ...) INHERITS (equipment.devices);
CREATE TABLE equipment.printers (brand, color, ...) INHERITS (equipment.devices);
```

**Секционирование (партиционирование):**
- Таблица `projects` разбита на месячные секции (январь-апрель 2025)
- Автоматическое распределение данных по секциям
- Архивация старых данных

**Представления (VIEW):**
- `department_view` — для таблицы отделов
- `first_department_employees` — только сотрудники 1-го отдела
- `WITH CHECK OPTION` — защита от некорректных вставок

**Файл:** `Лабораторная_работа_3_Федоренко.sql`

---

### Lab 4: Серверное программирование (PL/pgSQL)

Бизнес-логика на стороне базы данных.

**1. Функции**
| Функция | Назначение |
|---------|------------|
| `check_email_pattern(emails[], pattern)` | Валидация массива email'ов |

**2. Процедуры**
| Процедура | Функциональность |
|-----------|------------------|
| `update_employee_email(emp_id, new_email)` | Обновление email с проверками |

**3. Триггеры**
| Триггер | Событие | Назначение |
|---------|---------|------------|
| `check_login_password` | BEFORE INSERT/UPDATE | Валидация логина и пароля |
| `salary_before_update` | BEFORE UPDATE OF salary | Запрет повышения зарплаты >100% |
| `after_employee_insert` | AFTER INSERT | Аудит приема на работу |
| `after_employee_update` | AFTER UPDATE | Аудит изменений |
| `after_employee_delete` | AFTER DELETE | Аудит увольнения |

**4. Система аудита**
Таблица `job_history` автоматически сохраняет:
- Все поля сотрудника на момент изменения
- Дату и время события
- Тип операции (`INSERT`, `UPDATE`, `DELETE`)

**Файл:** `Лабораторная_работа_4_Федоренко.sql`

## Примеры использования

### 1. Проверка массива email'ов
```sql
SELECT check_email_pattern(
    ARRAY['user@mail.ru', 'test@gmail.com'], 
    '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$'
);
-- Результат: true
```

### 2. Обновление email сотрудника
```sql
CALL update_employee_email(1, 'new.email@company.ru', NULL);
-- Сообщение: Успех: Email сотрудника с ID 1 успешно обновлен
```

### 3. Добавление сотрудника с валидацией
```sql
INSERT INTO "Persons"."employee" 
(first_name, last_name, gender, birthdate, login, password, job_id)
VALUES ('Иван', 'Петров', 'М', '1990-01-01', 'ivan_petrov', 'securePass123', 1);
-- Триггер автоматически проверит логин и пароль
```

### 4. Попытка некорректного повышения зарплаты
```sql
UPDATE "Persons"."job" SET salary = 150000 WHERE id = 1;
-- Ошибка: Зарплата не может быть увеличена более чем на 100%
```

### 5. Просмотр истории сотрудника
```sql
SELECT * FROM "Persons".job_history 
WHERE id = 1 ORDER BY date_event DESC;
```

### 6. Работа с наследованием
```sql
-- Все устройства (из родительской таблицы)
SELECT * FROM equipment.devices;

-- Только компьютеры (со специфичными полями)
SELECT * FROM equipment.computers;
```

### 7. Секционированные данные
```sql
-- Данные автоматически распределятся по секциям
INSERT INTO partitions.projects (project_name, theme, date) 
VALUES ('AI Project', 'Python', '2025-02-15');

-- Запрос к конкретной секции
SELECT * FROM partitions.projects WHERE date BETWEEN '2025-02-01' AND '2025-02-28';
```
